# 第一轮正式训练

## 问题与入场依据

在方向和横移幅度已有固定权重收益的 v2 执行机制下，较小 actor 更新能否保护前飞联合恢复、普通速度跟踪与静止漂移，并让管道恢复窗持续向前。后向仍有 24/32 接触。若保持前飞和普通护栏而后向没有进一步改善，下一轮优先区分可见时间和可执行运动。若训练新增前飞接触或静止超线，再查课程和被执行层覆盖时的学习目标。

同种子从 `u640` 出发的 `1e-5` 节点在第 16 次更新没有前飞逼近接触，联合恢复 31/32。到第 32 次更新时仍为 31/32，只有 1/32 前飞接触。`3e-5` 相同节点的前飞接触为 3/32，联合恢复 29/32。较小更新的第 32 次节点总接触 28/192，前向 2/64，后向 24/32。所有普通通行与静漂均在相对同机制起点的工程护栏内。管道恢复窗平均 0.742 m，起点 0.726 m。管道静止漂移均值由 1.759 降到 0.297 mm。这些取舍支持试用较小学习率。 [较小学习率开发复算](CHECK-SHORT-R1-B-RECOMPUTED.json) · [原学习率开发复算](CHECK-SHORT-R1-RECOMPUTED.json)

## 固定训练契约

固定同一 `u640` 起点，终点为 `u896`，新增 256 次更新和 131,072 条训练转换。每次更新 32 环境各 16 步，两段各 128 次。每段 16 次带真实管道逼近和测量扰动的更新，112 次普通指令回放。使用 `m4-escape-lateral-recovery-v2`，PPO actor 学习率 `1e-5`，critic 学习率 `3e-4`。PPO 其他参数、奖励与执行配置随方法与课程 pin 冻结。训练种子 `51398110`。中间节点用于关闭复核，终点固定后进入统一独评。

首段继承 `u640` 的 actor、critic、两组 Adam 状态及累计计数。Python、NumPy、Torch CPU 和 CUDA、课程生成器以及 PPO 排序用本轮种子新开随机流。第二段从 `u768` 完整恢复网络、Adam、计数和 RNG，按照同一签名继续。同设备首批概率复算覆盖样本，物理环境、测量和侧让短时状态在段边界重新构建。

较小学习率短训练实测监督 490.3 秒。上一轮可比的 128 更新段监督 836 至 882 秒。这里采用两段，以观测第二次目标暴露与长回放的累计效果，并核验一次完整分段恢复。冻结时系统盘实测剩余 107.69 GiB，保留 30 GiB 系统空间，七臂 R6 的原件和末臂预留按上一轮实测估算约 46 GiB。 [训练及资源配置](FORMAL-R1-SPEC.json)
