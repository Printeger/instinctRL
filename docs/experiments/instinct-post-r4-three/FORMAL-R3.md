# 第三轮正式训练

## 问题与入场依据

固定同一 `u640`、25°、触发以及原 governor 和 ICS 时，非紧急裁零后的方向修正在 32 条后向初始轨迹中救回 23 条，接触变为 1/32，原臂为 24/32。总接触 25→2/192，前向 0/64 不变。新机制也优于同一开发种子上的 28° 原执行臂的 16/32 后向接触。最强收益发生于训练前。 [同权重物理原件](MECHANISM-R3-RECOMPUTED.json)

同机制短训第 16 次节点经普通回放，接触和联合恢复与起点一致，屋门和管道恢复进度增加。第 32 次节点再经 16 次目标更新，后向仍 1/32，管道恢复跨过更长距离且管道静漂降低，新增一条树干前飞接触。三个臂管道联合恢复均为 8/8。短训结果支持有限规模，优先保住机械获益和普通运动。第三轮问题是先回放普通任务、最后一次短目标暴露是否能让训练增益留在恢复、速度跟踪或静漂上，同时保住新执行的后向安全。第三轮关闭后的统一独评将给出该问题的最终配对数据，后续再由用户审查。 [两个短节点与起点](CHECK-SHORT-R3-RECOMPUTED.json)

## 固定训练契约

固定 `u640→u768`，新增 128 次更新，65,536 条训练转换。每次更新为 32 环境各 16 步，两段各 64 次。前 112 次普通任务回放，最后 16 次目标场景。采用 25° 与非紧急裁零后的方向修正，actor 学习率 `1e-5`、critic `3e-4`，其余沿用短训同一方法。训练种子 `679851548`。绝对更新 704、752、768 保存完整权重，预指定 `u768` 进入独评。

第一段继承同一 `u640` 的 actor、critic、两组 Adam 状态及累计计数，Python、NumPy、Torch CPU/CUDA、课程生成器及 PPO 排序从本轮种子开始。第二段从 `u704` 严格恢复相同配方的模型、Adam、计数和 RNG。仿真、测量历史和侧让记忆按段重新初始化。

32 次短训练实测监督 483.6 秒。128 次为短训练量的四倍，目标更新量与已测短训相同，适于检验更长普通回放，同时保留分段恢复证据。冻结时系统盘实测剩余 98.75 GiB，保留 30 GiB 系统空间。最新脱离快照的 26 组直接链 CPU 检查全部通过。 [固定配置与资源](FORMAL-R3-SPEC.json)
