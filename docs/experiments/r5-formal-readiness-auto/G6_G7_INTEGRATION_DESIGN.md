# Finite transition and checkpoint recalculation design

Design only, not a live authorization or completion evidence. Implement and prereview the exact source after the development candidate is known. No formal training is submitted by this Goal.

The current research contract supports only pure-hover training and original-Z evaluation. Existing `smoke_update` performs optimizer updates, and existing full evaluation has different scope/budget. Neither is an implicit authorization for this check. Add a narrowly bound mode to the existing entry rather than inventing an external GPU probe.

G6: one deterministic policy rollout, 112 steps ×32 lanes =3584 nontraining transitions, one fresh reset using the original Z initial-state construction and evaluation seed20260909. Commands are zero for steps0–15; +0.2m/s along the eight existing lane directions for16–47; negative along the same directions for48–79; zero for80–111. This is an implementation check, not a new Z/T/S/X/W performance metric. The policy continues to issue its own actions. Check actual actor input current-command slots, next-command staging, finite action/decoded command/reward/returned history and privileged separation, and reset/anchor lifecycle at the temporal boundaries. Retain each reset/failure and never splice history. A shape/index/reference defect fails this check; it does not justify a reward or threshold adjustment. No optimizer or checkpoint write is needed for this finite check.

G7: within the same accurately budgeted entry, load the actual accepted u1 checkpoint and frozen first512 input/probe from its own training run on the same CUDA device and implementation. Compare the actor's mean/std/logp against `first_update_probe.pt` last minibatch `after` row with original float32 atol1e-6/rtol1e-5. That actor boundary corresponds to the saved u1; its critic probe value precedes the final critic minibatch, so do not compare it to the completed-u1 critic as though synchronous. Do not sample actions or consume RNG, and verify actor/critic/optimizers are unchanged by the forward check.

For the selected final checkpoint, strict identity/seed/method/PPO/counter validation must use the accepted original source identity. Two independent loads can verify identical model/optimizer tensors and same-input forward consistency on that device. Such a comparison is reproducibility across loads, not a claim that a missing historical final-checkpoint output was recorded. Retain that distinction. Bind every checkpoint/input/probe path and SHA before release, and bound tensor-read output and resource limits. A future source with only integration changes needs an explicit reviewed compatibility binding; never substitute its commit as the training checkpoint's source.

Warm-start formal entry must restore actor, critic, both optimizers, RNG, counters and curriculum under an exact origin binding, then explicitly perform a fresh simulation reset. It cannot claim physical/history/anchor/actuator trajectory continuation. The formal command phase and global counters must be distinct so a 128-update hover checkpoint does not accidentally skip into the old mixed curriculum. Budget additional updates/transitions and actual Adam totals separately. This code and its tests still need implementation and independent acceptance before G8 can pass.
