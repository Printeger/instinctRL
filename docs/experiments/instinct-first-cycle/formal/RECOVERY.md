# 正式作业恢复

前两次作业在进入模拟器前退出。第一处是普通目录下 `native` 与作业根目录重叠，被写入保护拒绝。第二处是资源窗口中两个 RustDesk 进程和一个 GNOME 远程桌面进程触发原进程数判定。修复作用于本轮实际路径和远程桌面进程数量，GPU 空闲显存、利用率、时间窗口和未知进程检查继续执行。两次保留真实回执和收费时间，训练转换均为零。

第三次作业完成了原阶段 u640→u704 的 64 次更新。在首次进入延迟阶段时，重置后的第一个观测尚无可送达帧，H1 覆盖检查终止，第二阶段没有完成一次优化器更新。保留失败原件、三份 checkpoint、32,768 条转换和退出回执。u704 的模型身份和实际更新已检查。

选择从原始 u640 重跑一个完整的只增加周期性丢帧的候选，保持训练种子、轮数、0.01 m 噪声和其余方法。直接使用中途模型并改变课程需要另一套恢复身份和跨配方审计。重新运行从起点到终点全部执行，延迟启动覆盖检查保持原样。预算修订单列已发生的半程、一次重新初始化及实际证据，仍交付一条完整候选和一份候选全量评价。
