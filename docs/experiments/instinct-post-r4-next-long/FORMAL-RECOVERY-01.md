# 正式首段写入修复和重发

首发 `u768→u1280` 在完成 403 次更新后触发累计写入额度，实际采集 206,752 步，其中 416 步属于尚未完成优化的更新。保留 4 个中间节点、失败状态、原件和关闭回执。最后节点 `u1024` 的权重及两个 Adam 可读取。普通阶段的更新、minibatch 和 rollout 流缺少最后尾标，初发结果按原审计判为失败。正式链继续采用两段均闭合、各 512 次更新的原终点规则，从同一个 `u768` 重发。首发的训练消耗单列。 [失败原件索引](FORMAL-FAILURE-01.json)

7,274 次运行时资源检查写入同一个持续增长的 JSON。按每次写入时的实际完整前缀复算，累计约 5.03 GB，距离 6 GiB 上限已不足以写入下一次资源观测。历史完整 R6 约有 6,076 次同类检查，每臂累计约 3.45 GB。修复将下一阶段直接运行的每次检查改为按原行内容同步追加，关闭时一次性生成既有 JSON 汇总。内存阈值、采样时点、失败记录、STOP 和系统盘 30 GiB 守卫继续执行。 [修复与 CPU 回归](FORMAL-RECOVERY-01.json)

R6 保留冻结协议、每块 1.5 倍实测上浮额度、初始分母和评分。运行输入另绑定 5.5 GiB 全臂有效额度，比十个完整历史臂的最大实占高约 21%。该额度按逐条写入重新计算，不再为全量重复前缀预留。方案同时容纳失败原件、两段重发、开发剂量、四臂物理和四臂 R6。每个作业启动前按当前实际剩余容量复核。 [原独评冻结](INDEPENDENT-PROTOCOL.json) · [原逐块额度](R6-OUTPUT-PLAN.json)

恢复只涉及日志与资源。如果新的训练输入改变起点、课程、种子、方法、执行版本、检查点或终点，准备入口拒绝重发。正式端点绑定在两段均关闭后生成，物理和 R6 独评都使用原冻结随机流。 [重发配置](FORMAL-RETRY-01-SPEC.json)
