# instinctRL 第三轮训练任务需求书

本文件是供用户发起下一轮开发的任务草案。“第三轮”指 R6 结束后的新研究周期。仓库里出现本文件或示例 prompt 本身不构成运行授权。

## 目标与起点

回答一个可检验的问题：在 Paper-1 的测量和控制边界内，相比冻结基线及等训练量的原配方，一项明确的训练改动能否带来可重复、有实际意义的改善，同时守住原任务的安全与行为要求？改善、退化、未证实改善都是可交付的科学结论。资源不足或证据损坏要单列为未完成。

R6 的价值在于留下了可复核的基线、模型和评价证据。冻结的 u640 和三个从 u640 续训得到的 u768 在原五任务及 16 个最终条件均为每条件 32/32。旧成功率仍适合查退化，单靠它已无法分辨额外收益。TRAIN-01 与确认段 01B 都在执行大量更新后缺少可验证的终点 checkpoint；部分工作负载完成后又遇到清理超时。优先从这些事实复盘。总耗时、工具切换造成的返工及其因果关系只按记录归因，缺失项注明未知。参见 [R6 最终报告](../experiments/r6-direct-training/FINAL_R6_RESULTS.md)。

## 原始 idea 与边界

- 保持同一测量空间速度指令调节器。零指令时以冻结的有效测距观测为锚，在可观测方向抑制漂移；非零指令时依局部测量调节机体系速度指令，兼顾跟踪和安全。姿态稳定与底层指令执行继续交给既有飞控。几何退化时，结论要注明哪些运动无法由当前观测辨认。
- Actor 只接收批准的传感器与测量历史、有效性和时间、IMU 派生字段及指令。位姿、里程计、实际或显式估计速度、地图、SLAM、障碍真值和仿真私有状态不得直接或间接流入部署侧输入或指令调节链。沿用 reward、critic、评价和日志各自获批的特权用途。每个新增指标说明谁可读，特别核对归一化、缓存和历史特征。
- 以 [Paper-1 方法](../paper1_vel_ctrl.tex)、[平台锁定手册](../instinctRL_Development_Handbook_v1_1_platform_locked.tex) 和 [项目规则](../../AGENTS.md) 为依据。优化空间包括合法输入上的训练采样、课程和训练信号使用方式；涉及平台、传感器、控制接口、既有安全机制或原验收语义的变化另立提案。保留历史工作区、冻结 runtime、旧报告和失败原件。

## 工作与决策

| 步骤 | 需要回答的问题 | 完成证据 |
| --- | --- | --- |
| 复盘第二轮 | 时间实际花在哪里？哪些工作产生了科学信息，哪些是重算、等待或交付返工？ | 从已有回执、训练记录和发布记录中列出最有影响的瓶颈、证据、能省掉的步骤及必须保留的检查。能归因多少就报多少。 |
| 完善理论 | 在哪类合法观测与指令下，候选和基线应表现不同？什么结果会推翻这个解释？ | 一条主假设，写清机制、适用条件、预测、竞争解释和反证。例如零指令下测距锚误差相近，某一不可观测方向仍可能有不同漂移。该例只确定推断边界。 |
| 选定比较与改动 | 旧评价是否饱和？哪项指标能分辨实际差异？哪一个训练变量最值得改？ | 优先用既有开发数据检查指标分布、缺失、噪声与天花板。主指标可考察获批记录中的锚误差、跟踪表现或干预代价；明确单位、方向、最小有意义差异及安全护栏。保留旧任务查退化。只在证据支持时采用新机制，并说明怎样用对照区分它与单纯多训练。 |
| 实施并运行 | 能否在一次有限的比较中同时验证训法和执行可靠性？ | 比较冻结基线、等起点等更新量的原配方和候选。历史原配方仅在输入、预算和评价协议可比时复用，否则运行匹配对照。先验证 checkpoint 能写、读、恢复，作业能关闭，再运行主比较。保留原件，区分工作负载结果与监督器退出结果。 |
| 结论与方向 | 改善了什么，在哪些条件下失效，证据足以支持哪一步？ | 按预定规则给出结果、差值、不确定性、安全回归、耗时与资源；分别报告工程、学习效果与理论解释。给出优先级最高的下一步、预期区分的解释及放弃条件。 |

**正式训练前冻结决定。** 用一份简短实验计划固定起始 checkpoint、对照、候选唯一主要差异、训练量、随机种子、主指标、护栏、停止条件、预计墙钟时间与资源上限。对照和候选使用相同评价条件做配对；分别呈现训练随机流间的差异和评价样本的不确定性。共同 checkpoint 的续训按续训解释。开发数据用于选择指标和调参，新的最终保留集在方案冻结后使用；已查看的 R6 最终数据只用于历史比较和回归。若主指标不能区分候选、预算不足以覆盖有效对照或恢复机制不可靠，先解决具体问题，再投入长训练。

**控制开发成本。** Maverick 作为单一负责人，按问题进展决定借用视角或调用伙伴，同一目录单写者。沿用固定工作目录、main、既有训练实现和 [本地直接运行链](../../tools/r6_direct/README.md)。先检查该入口对本轮契约、作业命名和证据的实际支持；用新身份绑定本轮输入。只有现有入口出现可复现的具体阻碍时才做最小修复。不开启 rlflow 或旧 controller，不在轮中迁移工具，不将录像制作列入训练验收的关键路径。按项目规定提交并冻结精确 commit、tag、输入哈希和真实命令，在只读快照运行。STOP、进程清理与资源准入持续有效。

**存储。** 长期保存模型、复现输入、逐条件结果和必要证据。提前区分必须生成的原件与可选日志；本轮可再生中间文件按最后使用时间回收。分别报告单作业峰值和最终留存量。具体保留与回收条件见[第三轮计划](../experiments/third-training/PLAN.md#存储与保留)。

**运行与收尾。** 以新任务的授权为准，明确允许的本地仿真、训练、评价和资源范围。未给定且无现行授权可用的资源数值，由 Maverick 根据复盘提出一个可执行方案，在发车前集中确认一次。边界内的实现选择和可恢复故障由 Maverick 处理。出现重复故障时先说明新证据，避免原样重跑。触及 STOP、资源上限、不可恢复的证据问题或需要改变核心边界时停止新作业，保全证据，说明实际完成点。

最终交付一份结果摘要，链接冻结输入、模型、逐条件评价与运行回执。开头直接回答“训练完成了吗、候选相对谁改善了多少、下一步做什么”。末尾按 Maverick 的贡献记录说明实际贡献及改变决策的关键证据。无需为每个阶段新建报告体系。
