# 单分支开发流程

生效：2026-10-12。来源：用户在本次会话逐项批准整理方案，包括迁移、CPU 验证、
保留历史、提交和正常推送 main。此授权不增加任何实验或训练预算。

1. 进入固定目录，读取项目状态、当前任务授权、git status 和 HEAD。
2. 日常代码、必要工具、测试和状态在同一 main 分支维护；同一目录单写者。
3. 完成一个可理解的变更后提交。提交按实现职责组织，不设固定次数，不重写已有历史。
4. 实验前提交全部执行源码与配置，保存精确 commit、配置/工具/输入哈希及真实 argv。
5. 用 tag 标识实验输入与验收版本；用只读快照或 detached HEAD 固定运行版本。
   默认不创建任务分支。历史绝对路径绑定保留原 bytes，新候选记录新绑定。
6. CPU 检查、代码同步、独立验收和真实行为验证分别记录；通过测试不等于训练成功。
7. 运行开始后输入冻结。失败原始记录保留；离线重分析生成新记录。不得覆盖旧证据。
8. 用户授权内正常推送；不 force push、不改写历史。同步前核对远端继承关系。

项目状态的唯一阅读入口为 `docs/PROJECT_STATUS.md`；机器状态为 `coordination/PROJECT_STATE.json`。
历史 Commander/Executor 状态原文归档，不能当作新执行许可。

当前开发在 Codex 中默认由 Maverick 主持；入口为根 AGENTS.md 和项目级 maverick Skill。
每个新任务先取得五位子人格的独立判断，由 Maverick 综合后推进。同一任务恢复时沿用首轮记录，后续按问题进展定向追问，交付时引用证据说明贡献与关键思维转变。
Commander/Builder 是历史职责名称，不要求角色调度器或 rlflow。
本地训练、评价、分析入口见 `tools/r6_direct/README.md`；旧 Store/逐作业模型预审/
聊天会话或 RPC 状态不构成当前开发和直接运行的前置条件。
沿用 V3 的 MUST_FIX、NON_BLOCKING、FOLLOW_UP、
CONTRACT_DECISION 分类，实质缺陷按原任务局部修复，额外需求进入后续任务。
产品、actor、方法、runtime 和资源边界不因工作流调整改变。
live/训练是否授权按当前用户任务判断；2026-11-01 去耦任务仅执行实现与 CPU 检查。

## 训练规模与证据标准

新训练计划与结果报告按单个候选从指定起点实际新增的训练环境步数定档。
现行 PPO 每次更新采集 32 个环境各 16 步，共 512 步。采样批量改变时仍按环境步数定档，
并记录实际更新次数。GPU 用时单列为资源用量。作业准入和预算继续按当次用户授权判断。

| 档位 | 新增训练环境步数 | 按现行 PPO 换算 | 要回答的问题与最低证据 |
| --- | ---: | ---: | --- |
| 验证方法式短训 | 1–32,768 步 | 1–64 次更新 | 判断改动能否学到预期行为及是否出现明显退化。固定起点，用开发集比较起点与短训节点。归因到单项改动时，使用同起点、同预算对照。 |
| 有限规模的微调 | 32,769–524,287 步 | 65–1,023 次更新 | 判断已有模型能否改善具体问题并保住原能力。从已有权重出发，提前确定预算和检查点，比较同执行机制的起点与终点，报告改善项和退化项。 |
| 正式长训 | 至少 524,288 步 | 至少 1,024 次更新 | 检验增加训练量后收益能否保持、扩大或反转。开跑前冻结起点、配方、种子、最大预算、检查点和终点规则。预先规定关键场景的计数口径和最低覆盖量，记录学习曲线与分段恢复证据。终点锁定后，用独立留出与同执行机制的起点配对。 |

- 同一候选可核验的连续恢复各段累计进该候选的新增训练量。起点已有的步数、其他候选、
  未纳入该续训链的尝试及评估步数分别记账。
- 关键场景覆盖单独记录。例如研究后向避障时，数实际出现后向逼近的训练轨迹。
  总步数达到门槛且关键场景覆盖不足时，在报告中注明。
- 分别记录计划档位、实际用量、完成状态和科学结果。正式长训按冻结协议跑完并复核后，
  即执行完成，科学结果未达标则照实记录。计划为正式长训、提前中止且实际步数低于门槛时，
  记为「正式长训中止」，附实际用量。单种子结果适用于该配方和种子，跨种子稳定性由复跑检验。

历史命名、回执和归档保留原文。
